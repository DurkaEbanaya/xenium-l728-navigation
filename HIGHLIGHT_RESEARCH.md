# Настройка выделения L728 — v0.4.0 и история исследования

**Финальная версия установлена и подтверждена владельцем: «Работает идеально».**
SHA-256 логического MMI:
`34a2d7ab0a09ea41faabd5b232d25f0a8e6dbc8dcd01eeb3aa4bd41625d8b41c`.
Ниже сохранена история подготовки, обнаруженных ошибок и последовательных
исправлений. Фразы о предстоящих проверках относятся к соответствующему этапу.

Исходная версия: установленная и проверенная владельцем навигация + SOS без
вспышки, SHA-256 `41aba70fd84346095a756ccc97dcbb33b23dcca4c9dba686351622c93f1a7f34`.
Все адреса ниже виртуальные, база MMI `0x88000000`.

## Интерфейс

- Настоящее окно «Дисплей»: ID `0x90014`, callback `0x8831af24`.
- Дескриптор `0x883dd898..0x883dda80`, единственный указатель открытия
  по смещению MMI `0x31be64`. Это поток команд, завершаемый `F030`.
- Родитель строк — `0x901d5`. Строка `F110`, подпись `F10A`, selector `F10E`,
  пользовательская отрисовка `F10F`.
- Selector: добавление собственного UTF-16 item `0x8806d12c`, выбор
  `0x8806d36a`, получение индекса `0x8806d398`; уведомление окна `E0F0`.
- `F021` — создание окна; `F022` — закрытие. Штатный callback сохраняет
  собственные настройки, его нельзя подменять пустым обработчиком.

## Отрисовка

- `IMAGE_COMMON_SELECTED_BAR`, ID `0x4000001f`, — картинка, а не цвет SELECT.
  Исходный `sabm` + `ABMP` blob 48 байт, размер 1×144.
- Получатель картинки `0x881ed5c4(id, window, &length)` используется
  рисованием обычного и растянутого изображения. Первые 8 байт можно
  перенести без PC-relative инструкций.
- Kernel parser `0x80be60c2` подтверждает ABMP, big-endian размеры и числа
  палитры. Обычный BMP также поддерживается через `0x80bf1db8`.
- Цвет букв обычного списка `0x88040a0c`: состояние 1 — выделенная строка,
  0 — обычная, 2/3 — отдельный штатный стиль.
- Второй путь меню: вызовы `0x880a328e` по адресам `0x886c6126`,
  `0x886c7b46` и бегущего текста `0x880a34cc` по `0x886c60c6`,
  `0x886c7aec`. Цвет — halfword пятого stack-параметра (`sp+20`),
  независимый от resource font. Адаптер меняет его только при совпадении
  текущего индекса `r9` с `[r4+0x96]` и отсутствии disabled flag `0x1000`.
  Вызовы бегущего текста находятся внутри подтверждённых selected branches.

## Сохранение и память

- Родные файловые API: create `0x881d2d02`, read `0x881d36ba`, write
  `0x881d3710`, close `0x881d366a`. Штатный SSL код читает с flags `0x31`,
  записывает с `0x52`; read/write возвращают 0 при успехе и count через указатель.
- Новая настройка хранится в отдельном файле. Drive D используется
  FOTA и системными файлами; drive E используется альтернативными файлами.
  Проверки файловых отказов и восстановления выбора выполняются также в модели;
  окончательная версия получила общее подтверждение владельца на аппарате.
- MMI обслуживается demand-paging: kernel `0x80a9ea02` обрабатывает fault,
  читает FTL `0x80a9eb3a`, затем меняет page mapping. Записывать изменяемое
  состояние в MMI payload нельзя: при вытеснении оно будет потеряно.
- RAM объект выделяется через `0x88091b60` с проверкой NULL, регистрируется
  `0x88313370`, находится через `0x88313484`. Тип `0x484c3732` намеренно
  непрозрачный: существующие UI walkers распознают только типы 1/2/3.
  Выполнение реального resolver подтвердило, что он игнорирует этот объект.
- Конец установленного кода `0x7e162c`, свободный хвост текущего образа
  только 468 байт. Дополнительные страницы блока `0x17c` пусты по main,
  их main проверяется по исходному дампу перед подготовкой пакета.
- Выполнен настоящий kernel scatter decompressor `0x81463738`:
  запись `{source=0x81591ba0,dest=0x81700000,size=0x57504}`.
  В восстановленной таблице `0x817001e0` MMI регион имеет базу `0x88000000`
  и размер `0x01000000` (16 МБ). Кандидат занимает менее 8 МБ.

## Состояние

Кандидат собран поверх указанной установленной версии. В «Дисплей» добавлены
«Фон выделения» (стандартный, жёлтый, зелёный, белый, оранжевый, красный,
чёрный), «Буквы выделения» (стандартные, чёрные, белые, жёлтые) и образец
«АБВ 123». Сохранение: отдельный файл `D:\l728-highlight.cfg`, 8 байт с
версией, границами индексов и контрольным байтом. Ошибка записи оставляет
надпись «Не сохранено» и повторяет попытку при закрытии окна.

Целевые проверки выполняют код кандидата, реальные registry/трамплины,
kernel decompressor, обычные/выделенные/disabled menu branches и обрезку
образца. IO helper использует штатный заголовок 0x200 и ARM→Thumb stub,
поскольку FDL `data_exec` начинает выполнение с адреса загрузки +0x200.
Проверка `tools/check_highlight_io.py` запускает именно этот адрес и
проверяет 78 сочетаний magic/операции/блока: допустимые доходят до
инициализации, остальные возвращаются до первого обращения к NAND.
Файловая система, widgets и LCD в них моделируются; это не
аппаратная проверка. Существующие навигационные и SOS изменения сохранены
побайтно. Финальный аппаратный результат описан в конце документа.

## Воспроизведение финальной сборки

Из корня клона, после `build_navigation.py` и `build_sos.py --no-flash`:

```sh
python3 -B tools/build_highlight.py --folder experimental/highlight-release
python3 -B tools/check_highlight.py --folder experimental/highlight-release
python3 -B tools/check_highlight_background.py --folder experimental/highlight-release
```

Нужны clang/LLD, objcopy, Python с capstone, pyelftools и unicorn, а также
приватные исходные user/kernel для выполнения реальных native paths.
Builder не перезаписывает каталог с существующим transition-планом.
Ожидается указанный в начале SHA-256; это логический образ, не NAND-пакет.

## Историческая цепочка сборки и установки

Следующие команды документируют проведённую сессию. Текущий builder создаёт
финальную версию, поэтому не воспроизводит промежуточные образы, закреплённые
хешами в старых планах. Для исторических transitions нужны сохранённые приватные
артефакты всех предыдущих этапов. Установка из stock отдельным инструментом
не реализована. Все относительные команды ниже выполнялись из корня проекта.

```sh
python3 -B tools/build_highlight.py
python3 -B tools/check_highlight.py
python3 -B tools/build_highlight_io.py
python3 -B tools/highlight_transition.py --prepare
python3 -B tools/highlight_transition.py --check-plan
```

`--prepare` применяется один раз для нового пакета. Артефакты приватные,
в `experimental/highlight/`. Пакет содержит before/after и точный откат
к работающей навигации + SOS. Меняются 6 блоков: `13d`, `13f`, `14c`,
`155`, `173`, `17c`; остальные страницы и OOB/FTL вне ECC сохранены.
Отдельный IO helper разрешает запись только этих блоков и чтение 10 блоков
полного известного footprint. Общие исторические helpers не изменены.

Подключение: сначала в терминале владельца запустить
`sudo python3 -B tools/start_highlight_validation.py`, затем подключить
телефон без батареи, удерживая UP. Скрипт загружает FDL, проверяет BootROM,
свежие блоки и аппаратный ECC в RAM; NAND не записывает. После успеха:

```sh
python3 -B tools/highlight_transition.py --apply --confirm-destructive-write
```

Откат в той же FDL-сессии:

```sh
python3 -B tools/highlight_transition.py --restore --confirm-destructive-write
```

Новая сессия требует повторного запуска startup; проверка допускает только
точные before/after состояния. Для восстановления повреждённого после
прерванной записи блока требуется отдельная диагностика: startup preflight
намеренно остановится на неизвестном состоянии. Откат возвращает код,
отдельный файл настройки в файловой системе не удаляет.

Первое подключение прошло BootROM и начальную RAM-диагностику, но чтение
первого блока остановилось из-за неверного формата входа IO helper.
Заголовок/entry исправлены и проверены от фактического адреса FDL.
NAND не записывалась; hardware_validated остаётся false до новой проверки.

Инструменты подключения хранятся постоянно в `build/spreadtrum_flash/`:
`spd_dump` и `t117_fdl/t117_fdl1.bin`. Источник upstream commit
`3d0582579f3521f35a4937b2e871312e4dd6c308`; в `spd_dump` добавлен параметр
`--fdl-loaded` для продолжения существующей FDL-сессии. Startup сохраняет
журнал и результаты диагностики в `build/`; `/tmp/opencode` нужен только
для одноразовых буферов перехода и создаётся автоматически.
Проверка наличия инструментов и пакета без USB:
`python3 -B tools/start_highlight_validation.py --check-tools`.

## Перезагрузка при входе в списки: исправление ARM interworking

Первый кандидат `6ae6b34e…` установлен: журнал
`experimental/highlight/transition/apply-1791967472083811641.json` содержит
точный readback 6 изменённых и итоговую сверку 10 блоков. Владелец сообщил
перезагрузку при входе в настройки и контакты; откат запретил.

Подтверждённая ошибка — принудительный Thumb bit на импортном malloc:
`0x88091b60` содержит ARM `ldr pc,[pc,#-4]` и Thumb-указатель ядра
`0x81082409`. Макрос FN выставлял bit0 и передавал управление на
`0x88091b61`, то есть интерпретировал ARM veneer как Thumb. Вызов происходит
при первом создании RAM состояния из общего обработчика выделения.

Исправление использует ARM_FN только для этого veneer. Новый регрессионный
check исполняет настоящий ARM veneer и моделирует allocator уже за ним;
установленный кандидат воспроизводимо падает на проверке режима, исправленный
проходит (также NULL allocation и все прежние UI/file сценарии). Прежняя
модель перехватывала veneer до исполнения и скрыла ошибку режима.

Исправленный кандидат:
`d0db149565c8a7e163c1d402ddbcd9bc0196b47d3709396689bc415e3495cabf`.
Отличается ровно одним байтом: user offset `0x7e1904`, `61 → 60`;
физический блок `0x17c`, страница 3. Пакет
`experimental/highlight-arm-fix/transition/` рассчитан от установленного
цветового кандидата, содержит исправленный ECC и сохраняет остальные
страницы/OOB/FTL. Это обновление, не восстановление предыдущей прошивки.

```sh
sudo python3 -B tools/start_highlight_validation.py --arm-fix
# После свежей аппаратной проверки:
python3 -B tools/highlight_arm_fix_transition.py --apply --confirm-destructive-write
```

Исправление записано после свежей проверки исходных блоков и аппаратного
ECC. Журнал `experimental/highlight-arm-fix/transition/apply-1791967867751476320.json`:
изменён только блок `0x17c`, readback SHA-256
`03f1a45fadf95f95ab0059436cb87a2e2d189c60676a6007e3fc7bc2e03a368d`,
финальные 10 блоков сверены, `completed=true`. Откат не выполнялся.
Владелец подтвердил устранение исходного сбоя; вход в «Дисплей» ещё вызывал
перезагрузку. Следующее исправление подготовлено без отката.

## Перезагрузка при входе в «Дисплей»: заголовок selector

Родной `0x8806d0dc(control, resource_id)` получает текст через
`0x881e8a2a → 0x886e8dc4`, обходя перехваченный `0x881ed668`.
Собственный ID заголовка `0x40fe0001` попадает в lookup как модуль `0xfe`;
`0x886e7caa` требует модуль `< 0x40` и вызывает assert. Установленный
ARM-fix образ воспроизводимо падает в новой целевой проверке этого пути.

Исправление передаёт готовую UTF-16 `String` в родной setter
`0x8806d06c(object, &caption, 1)`, получая object через `0x8806d6f8`.
Новая проверка выполняет настоящие функции добавления/клонирования items,
связные списки, выбор индекса и копирование заголовка; kernel allocation и
memory services моделируются за настоящими ARM veneers. Проверены обе
новые строки: 7 и 4 варианта, текст заголовков, целостность списков.
Создание остальных widgets и LCD остаются моделью, проверка на аппарате нужна.

Кандидат `57d62712c24d8d62221c295f28ec28467d8b00b7638a68a6a3a7da2e4c2ff894`
в `experimental/highlight-display-fix/`. Он собран с сохранением ARM malloc fix,
навигации и SOS. Перелинковка сдвинула адреса payload, поэтому обновляются
6 блоков `13d/13f/14c/155/173/17c`. Переход начинается строго с установленного
`d0db1495…`, а не с ранней прошивки. Остальные страницы и FTL/OOB вне ECC
сохраняются; аппаратный ECC и свежие 10 блоков проверяются до записи.

```sh
sudo python3 -B tools/start_highlight_validation.py --display-fix
# После свежей аппаратной проверки:
python3 -B tools/highlight_display_fix_transition.py --apply --confirm-destructive-write
```

Исправление установлено после свежей аппаратной проверки ECC. Журнал
`experimental/highlight-display-fix/transition/apply-1791968586655271760.json`
подтверждает запись и точный readback всех 6 блоков, итоговую сверку 10 блоков
и `completed=true`. Ожидается проверка владельцем входа в «Дисплей», выбора
цветов и сохранения после перезапуска.

## Вертикальная полоса вместо фона: сохранение sabm

Владелец подтвердил: перезагрузок больше нет, цвет букв работает идеально,
но цветной фон выглядит как вертикальная полоса слева. Установленная версия
`57d62712…` возвращала обычный BMP 1×144 вместо штатного `sabm` контейнера.
`0x88354cc0 → 0x881ac3a0` распознаёт `sabm`; при отсутствии контейнера
обычная отрисовка `0x883553dc` ограничивает source шириной BMP через
`0x88355350`, то есть одним пикселем. Именно этот clamp воспроизведён
на установленном образе: прямоугольник 240×30 становится 1×30.

Новый генератор сохраняет точную 12-байтную штатную обёртку
`7361626d0801010000010090` перед каждым цветным BMP. Её flag `0x08`
включает nine-slice обработчик `0x881ad030`. Формат BMP, размеры 1×144,
цвета RGB565 и все пользовательские параметры остаются прежними.

`tools/check_highlight_background.py` выполняет настоящий kernel BMP parser
`0x80bf1db8` (включая RGB565 masks), родной sabm renderer `0x881ac3e4`,
обрезку и nine-slice loops. Для шести цветов проверено заполнение всех
240 столбцов строки и отдельный clipped rectangle с guard bytes.
Декодирование пикселей в scratch buffer и конечные pixel callbacks
моделируются; это не замена проверки на LCD аппарата.

Кандидат `34a2d7ab0a09ea41faabd5b232d25f0a8e6dbc8dcd01eeb3aa4bd41625d8b41c`
в `experimental/highlight-background-fix/`. Переход начинается с установленной
Display-fix версии; меняются 3 блока: `17c` (страницы 3–6), `155` (55),
`13d` (0). Все renderer hooks совпадают побайтно с установленной версией.
После свежей проверки исходной версии и аппаратного ECC исправление записано.
Журнал `experimental/highlight-background-fix/transition/apply-1791969338282538737.json`
подтверждает readback всех 3 обновлённых блоков, финальную сверку 10 блоков
и `completed=true`. После установки владелец подтвердил: **«Работает идеально»**.
Это финальный проверенный образ v0.4.0; последующих записей не потребовалось.

```sh
sudo python3 -B tools/start_highlight_validation.py --background-fix
# После свежей аппаратной проверки:
python3 -B tools/highlight_background_fix_transition.py --apply --confirm-destructive-write
```
